What does the Referer header really do?

Every request your browser makes can carry a Referer header naming the page you came from. Edit a target and a referer below, send a real request, and see exactly what the server receives.

Read this first. A page like this — running in a browser — cannot forge the Referer to any value you like. Browsers block JavaScript from doing that on purpose. This lab shows you the real behaviour, then shows you the terminal tools that can forge it. That gap is the whole lesson: never trust the Referer header to prove who's asking.

4 How it's actually forged

    

      
Referer spoofing is real — it just doesn't happen in a sandboxed browser tab. It happens in tools where the person writing the request controls every header. Run these in a terminal and the target genuinely receives your faked Referer.

Other routes to the same result: an intercepting proxy (Burp Suite, mitmproxy), a header-rewriting browser extension, or a server-side script that relays the request. The common factor is that the attacker owns the request — so the header proves nothing about them.

    

  


  
  

    
5 Why this matters — Unit 2 notes

    

      

        
The Referer is a hint, not an identity.

        
It's set by the client, and any client that isn't a locked-down browser tab can set it to anything. Treat it as trivia about traffic, never as proof of origin.

        
Referer-based access control is broken by design.

        
"Only allow requests that came from our own site" fails the moment someone uses curl -e. Real controls use secrets the attacker can't guess: session tokens, signed requests, anti-CSRF tokens tied to the session.

        
Browsers protect the header on purpose.

        
The reason this lab can't fake the value is the same reason the web mostly works: JavaScript on one site can't impersonate a request from another. That boundary (the same-origin policy) is doing real work.

        
Stripping the referer is legitimate — and easy.

        
Setting Referrer-Policy: no-referrer keeps your users' internal URLs out of other people's server logs. That's a privacy control you can apply, unlike forging.
